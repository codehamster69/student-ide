## What happened

The phase 1 editor worked but looked like a prototype. Rohan asked for a
professional UI with motion graphics, free to pick the stack. The
student-facing screens (sign-in, consent, task picker, editor, run output,
finish dialog, saved screen) were rebuilt in `frontend/src/` with React 18,
Tailwind CSS v4 and Motion (Framer Motion). A design system in
`frontend/src/ui/` (colour tokens with light/dark themes, motion presets,
Button/Field/Checkbox/Badge/Dialog/Stepper/RhythmBars primitives) is meant
to be reused by the teacher timeline dashboard (build step 3). The
CodeMirror editor got a theme built from the same tokens.

`recorder.ts` and `capture.ts` (everything that produces events) are
byte-for-byte unchanged, and the event schema is still v1.

## Why

- **React + Tailwind + Motion** over staying with plain DOM code: the
  dashboard will be much larger than the student editor and needs reusable
  components; Tailwind keeps tokens and layout in one place; Motion gives
  spring/presence animations without hand-written state machines.
  Svelte or Vue would also work, but React has the widest ecosystem for the
  charting the timeline will need.
- **Motion must not disturb keystroke timing**, which is the thesis's raw
  signal. Three rules:
  1. CodeMirror is created once in an effect and never re-rendered by
     React, so typing triggers no React work.
  2. Animations run only on discrete actions (run, dialog, screen change)
     and animate only opacity/transform (compositor-friendly). The only
     constant animation in the editor is the CSS "Recording" pulse.
  3. Key times come from `KeyboardEvent.timeStamp` (event creation time),
     so even a busy main thread would delay handling, not the timestamp.
- **No React StrictMode**: its double-run effects would create a second
  editor and log a duplicate start snapshot.
- The native `confirm()` for Finish became an in-page dialog, so the e2e
  test now clicks "Finish session" in the dialog.
- Consent wording is unchanged (ethics approval covers that text).
- The sign-in screen shows a self-typing code card with a live
  keystroke-rhythm strip: it explains in one glance what the tool looks at.

## Evidence

- e2e (`frontend/e2e/record.mjs`) passes: 214 events with the same per-type
  counts as before the redesign (key 136, edit 64, snapshot 3, focus 4,
  cursor 3, clipboard 1, run 1, start/end 1 each); replay matches the run
  code; median inter-key gap 49.7–50.4 ms over 3 runs (48.1 ms before; the
  gaps are set by Playwright's typing delays).
- New assertion: zero main-thread long tasks (>50 ms) during the typing
  window, in all 3 runs.
- Screenshots: `thesis/latex/snapshots/ui-redesign/` (before-*, after-light-*,
  after-dark-*), regenerated by `frontend/e2e/screenshots.mjs`.
- Text and figure: `thesis/latex/chapters/04-system-design.tex`,
  subsection "Student interface", `fig:ui-before-after`.
