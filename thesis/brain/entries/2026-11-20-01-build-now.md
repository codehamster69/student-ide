## What happened

Rohan saved v2 of the "CS303 (Python)" Sandbox Labs environment (adding pandas)
and it stayed at "Queued to build". The server never builds images: the GitHub
Actions workflow `sandbox-env-images.yml` polls `/api/sandbox/builds`. Its cron
says every 10 minutes, but GitHub ran it only every 6 to 8 hours (runs at
2026-11-19 09:26, 18:35, 2026-11-20 00:54 UTC), so the version waited for the
next scheduled run. Token and queue were fine. A manual `workflow_dispatch`
built it.

Fix: `backend/studentide/build_kick.py` sends `workflow_dispatch` when a version
is queued (saved or approved), if `STUDENTIDE_BUILD_DISPATCH_TOKEN` is set. New
`POST /api/sandbox/environments/{env}/versions/{v}/build` (Build now on a queued
version, Try again on a failed one, which re-queues it). The environment panel
polls while a build is queued or building. The schedule stays as a fallback.

## Why

Alternatives: build on the VM (rejected in PR #40: the student-facing VM must
not hold the Docker socket for arbitrary recipes or spend its CPU on builds);
a self-hosted runner (one more machine to keep up); shorter cron (GitHub's
throttling is the problem, not the interval). Dispatch keeps the existing
off-VM design and needs only a narrow token (Actions: write on one repository).

## Evidence

`backend/tests/test_sandbox.py::test_build_now_starts_the_workflow`; workflow
run 44698089130 (manual dispatch) built the pandas image.

## Follow-ups

Set `STUDENTIDE_BUILD_DISPATCH_TOKEN` in the VM's deploy.env and redeploy.
